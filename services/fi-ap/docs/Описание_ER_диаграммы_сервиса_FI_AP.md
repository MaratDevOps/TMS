# Описание ER-диаграммы сервиса FI-AP

Диаграмма `ER_диаграмма_сервиса_FI_AP.PlantUml` описывает минимальную модель
вспомогательного сервиса FI-AP. В данном документе подробно рассмотрены таблицы
`Outbox` и `OutboxDeliveryAttempts`, обеспечивающие надёжную публикацию событий
`payment.demand` в Kafka.

## Общий принцип

При создании или изменении `OpenVendorItem` сервис в рамках одной транзакции:

1. сохраняет данные открытой позиции кредитора;
2. создаёт неизменяемую запись `Outbox` с подготовленным Kafka-событием.

Если транзакция завершается ошибкой, не сохраняется ни одна из этих записей. Поэтому
сохранённому изменению открытой позиции всегда соответствует запись `Outbox`.

Отправка в Kafka выполняется отдельно фоновым обработчиком. Каждая попытка отправки
фиксируется в `OutboxDeliveryAttempts`. Данные о доставке не записываются в `Outbox`,
поэтому исходное событие остаётся неизменным, а полная история попыток сохраняется.

## Таблица Outbox

Таблица содержит события, подготовленные для отправки в Kafka. Одна открытая позиция
может иметь несколько событий: первое создаётся при появлении позиции, последующие —
при её изменениях.

| Реквизит | Тип | Обязательность | Описание |
|---|---|---|---|
| `eventId` | `UUID` | Обязательный, PK | Уникальный идентификатор события и первичный ключ записи `Outbox`. Повторная отправка того же события выполняется с прежним `eventId`; новое изменение позиции получает новый `eventId`. |
| `aggregateId` | `UUID` | Обязательный, FK | Идентификатор объекта, породившего событие. Ссылается на `OpenVendorItem.id` и связывает событие с конкретной открытой позицией кредитора. |
| `aggregateType` | `string` | Обязательный | Тип объекта-источника события. Для данной модели имеет фиксированное значение `VENDOR_OPEN_ITEM`. Позволяет однозначно интерпретировать `aggregateId`. |
| `eventType` | `string` | Обязательный | Логический тип события. В текущей реализации имеет значение `payment.demand`. Не следует смешивать с именем Kafka-топика: тип описывает назначение сообщения, а топик — место его доставки. |
| `eventVersion` | `string` | Обязательный | Версия структуры события `payment.demand`. Используется получателем для выбора совместимого формата обработки. Это версия контракта, а не порядковый номер изменения открытой позиции. |
| `topic` | `string` | Обязательный | Kafka-топик назначения. В текущей реализации — `payment.demand`. Хранение значения в записи позволяет зафиксировать маршрут события в момент его создания. |
| `messageKey` | `string` | Обязательный | Kafka key сообщения. Равен `OpenVendorItem.sourceLineItemId`. Одинаковый ключ направляет события одной открытой позиции в одну Kafka partition и сохраняет порядок их обработки в пределах этой partition. |
| `payload` | `JSON` | Обязательный | Полностью сформированное тело события в версии, указанной в `eventVersion`. Сохраняется в готовом для публикации виде, чтобы повторные попытки отправляли то же содержимое. |
| `occurredAt` | `datetime` | Обязательный | Момент возникновения бизнес-события — создания или изменения открытой позиции. |
| `createdAt` | `datetime` | Обязательный | Момент сохранения записи в `Outbox`. Может отличаться от `occurredAt` из-за времени обработки исходной операции. |

Запись `Outbox` после создания не изменяется и не содержит статус публикации.
Факт и результат доставки определяются по связанным записям
`OutboxDeliveryAttempts`.

## Таблица OutboxDeliveryAttempts

Таблица хранит отдельную запись для каждой попытки публикации события. Связь
`Outbox ||--o{ OutboxDeliveryAttempts` означает, что событие существует до начала
отправки и первоначально может не иметь ни одной попытки.

| Реквизит | Тип | Обязательность | Описание |
|---|---|---|---|
| `id` | `UUID` | Обязательный, PK | Уникальный идентификатор конкретной попытки доставки. |
| `eventId` | `UUID` | Обязательный, FK | Ссылка на отправляемое событие `Outbox.eventId`. |
| `attemptNumber` | `integer` | Обязательный | Последовательный номер попытки для одного события, начиная с `1`. Пара `eventId + attemptNumber` должна быть уникальной. |
| `status` | `string` | Обязательный | Текущее состояние попытки: `PROCESSING`, `PUBLISHED`, `FAILED` или `INTERRUPTED`. |
| `startedAt` | `datetime` | Обязательный | Момент начала попытки публикации. |
| `finishedAt` | `datetime` | Необязательный | Момент завершения попытки. Не заполняется, пока попытка находится в статусе `PROCESSING`. |
| `nextAttemptAt` | `datetime` | Необязательный | Рассчитанный момент следующей допустимой попытки после ошибки. Используется для задержки и управления повторными отправками. Для успешной попытки не заполняется. |
| `publisherInstance` | `string` | Обязательный | Идентификатор экземпляра фонового обработчика, который взял событие в работу. Помогает анализировать параллельную обработку и зависшие попытки. |
| `lockedUntil` | `datetime` | Обязательный | Срок действия блокировки события данным обработчиком. До наступления этого времени другой обработчик не должен начинать параллельную отправку того же события. |
| `partition` | `integer` | Необязательный | Номер Kafka partition, подтверждённый брокером после успешной публикации. |
| `offset` | `long` | Необязательный | Kafka offset опубликованного сообщения. Заполняется вместе с `partition` после подтверждения брокера. |
| `errorMessage` | `string` | Необязательный | Диагностическое описание ошибки. Заполняется для неуспешной или прерванной попытки и не должно содержать секретные данные. |

## Статусы попытки доставки

- `PROCESSING` — попытка создана, событие заблокировано обработчиком и отправляется;
- `PUBLISHED` — Kafka подтвердила запись сообщения; заполнены `finishedAt`,
  `partition` и `offset`;
- `FAILED` — попытка завершилась ошибкой; заполнены `finishedAt`, `errorMessage`
  и, если предусмотрен повтор, `nextAttemptAt`;
- `INTERRUPTED` — обработчик не завершил попытку штатно, например остановился после
  её начала. После истечения `lockedUntil` событие может быть взято повторно.

Статус изменяется только в записи конкретной попытки. Новая повторная отправка
создаёт новую строку с увеличенным `attemptNumber`, поэтому сведения о предыдущих
попытках не перезаписываются.

## Определение состояния события

Текущее состояние доставки события определяется по его последней попытке:

- попыток нет — событие ожидает обработки;
- последняя попытка имеет статус `PROCESSING` и блокировка действует — событие
  отправляется;
- последняя попытка имеет статус `PUBLISHED` — событие успешно опубликовано;
- последняя попытка имеет статус `FAILED` — событие ожидает повторной отправки либо
  признано окончательно ошибочным согласно политике повторов;
- последняя попытка имеет статус `INTERRUPTED` — после освобождения блокировки
  разрешается новая попытка.

После получения статуса `PUBLISHED` повторная автоматическая публикация события
с тем же `eventId` не выполняется.
