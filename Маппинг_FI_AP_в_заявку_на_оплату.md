# Маппинг: открытая позиция кредитора FI-AP → заявка на оплату

**Источник:** `Open Vendor Item (FI-AP) / Открытая позиция кредитора`  
**Получатель:** `Payment Request / Заявка на оплату` в TRM  
**Кардинальность:** одна открытая позиция, доступная к оплате → одна заявка (`1 → 1`).

## 1. маппинг реквизитов

| Реквизит FI-AP | Реквизит заявки на оплату | Правило преобразования |
|---|---|---|
| Кредитор (`Vendor`) | Контрагент (`Counterparty`) | Передаётся технический идентификатор контрагента/Counterparty.|
| Сумма (`Amount`) | Сумма (`Amount`) | Передаётся без преобразования; сумма должна быть больше нуля. |
| Валюта (`Currency`) | Валюта (`Currency`) | Передаётся код ISO 4217 без преобразования. |
| Срок оплаты (`Due date`) | Срок оплаты (`Due date`) | дата, к которой обязательство должно быть оплачено согласно условиям платежа в FI |
| Код компании (`BUKRS`) | Код компании (`BUKRS`) | Передаётся внутрикорпоративный код компании. |
| Документ-основание (`Origin document`) | Документ-основание (`Origin document`) | Передаётся структура где первая пара ключ-значение  Код компании (`BUKRS`), вторая пара: "BLART" - текстовое представление кода типа документа внутри корпоративной системы, третья: "Code"- Строковое представление номера документа в рамках системы FI|
| Назначение платежа (`reference`)  | Назначение платежа (`reference`) | Передается строка |
| Статус (`Status`) | Статус (`Status`) | Статус заявки может меняться как в системе FI так и в TRM. |
| Номер FI-позиции (`number FI position`) | Номер FI-позиции (`number FI position`) | представляет из себя струтктуру элементов ключ значение:{BUKRS(Код компании); `BLART` (тип документа) + GJAHR (год) + number FI position (номер позиции)}. |
| Тип платежа (`Payment method`) | Тип платежа (`Payment method`) | Значение определяется по единому классификатору типов платежа. |
| Блокировка платежа (`Payment block`) | Блокировка платежа (`Payment block`) | Логический признак: `true` — платёж заблокирован, `false` — блокировка отсутствует. |
